> **用途**: 定义 v0.1 的全部验收标准，作为提测、Review 和发布判断的唯一依据。
> **总通过口径**: 见第 1 节。

## 1. 总通过口径 (v0.1 Gate)

> **v0.1 通过验收，需要同时满足以下条件：**
>
> 核心玩法、UI、音效、反馈、性能和观测证据都达到本文档的标准。
>
> 每条验收标准都有对应的**测试记录、截图、帧序列、日志、状态快照或人工复核记录**作为证据。证据缺失即视为未达标。
>
> **不为了让实现过关而降低验收标准、测试要求或事实源口径。**
>
> **UI 风格事实源**: `design_imgs/主页.png`、`design_imgs/附页1.png`、`design_imgs/附页2.png`、`design_imgs/附页3.png`、`design_imgs/ui组件设计参考.png`。最终页面产出不要求像素级复刻，但样式风格必须严格符合这些样例图；若文字描述与样例图风格冲突，以样例图风格为准。
>
> **中文产出口径**: 样例图中的英文只作为布局、视觉密度和组件层级参考；最终页面的导航、标题、按钮、卡片、弹窗、题目、提示、AI 回复和验收截图必须为自然简体中文。
>
> **页面布局底线**: 样式允许细节调整，但整页布局结构至少保持样例图不变，包括左侧导航、顶部栏、主内容区、卡片区块、课程网格、学习页右侧 AI 面板、个人中心左右列和浮层组件位置关系。
>
> **Codex 自主视觉验收**: UI 验收必须由 Codex 自主打开页面、截图、保存日志、读取截图内容、自我检查问题并迭代修复。没有截图、日志、自检记录和复查结论，视为验收失败。

## 2. 验收标准类别

| 类别 | 权重 | 说明 |
|------|------|------|
| P0: 核心玩法 | 阻断级 | 必须完全通过，任一失败则阻塞发布 |
| P1: UI 与交互 | 高 | 必须通过，小瑕疵可记录但不阻塞（需修复计划） |
| P2: 反馈与动效 | 中 | 必须 >= 85% 用例通过 |
| P3: 性能 | 高 | 达到性能基线，未达标需有优化方案 |
| P4: 安全与兼容 | 中 | 安全无高危，兼容主流浏览器 |
