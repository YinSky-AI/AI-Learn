# 题库生成方案改进建议

> 基于实际执行 v0.1 题库生成过程中发现的问题总结

---

## 一、题目来源策略：从纯 AI 生成转向"种子 + 变式"

### 当前问题
- 完全依赖 AI 从零生成 5460 道题，去重后实际有效题仅 5471 道（原始生成约 7000+ 道，去重率约 22%）
- 大量题目语义重复（同一知识点换了数字或表述），浪费 Token 和计算资源
- 题目质量参差不齐，部分题目 explanation 为空或 content 过短

### 改进方案

**1. 建立种子题库（Seed Bank）**

| 内容 | 说明 |
|------|------|
| 种子来源 | 人工精选的高质量题目（每知识点 3-5 道） |
| 种子格式 | 参数化模板：`题干模板 + 变量槽 + 答案公式` |
| 示例 | `"{name}有{a}个苹果，给了朋友{b}个，还剩____个"` → 答案公式：`a - b` |

**2. 变式生成引擎**

```
种子题 → 参数替换（数字/场景/名称） → 选项重排 → 干扰项自动生成
```

- 同一道种子题通过参数替换可生成 10-20 道变式题
- 确保变式题在知识点层面不重复，但在具体数值/场景上不同
- 大幅降低去重压力，提高生成效率

**3. AI 仅用于"创意补充"**

- 种子题库覆盖 80% 的基础题和常规变式
- AI 仅负责生成剩余 20% 的"创新题型"和"综合应用题"
- 这样既保证质量又控制成本

## 二、语言一致性：增加生成前约束 + 生成后检测

### 当前问题
- 434 道英文题目混入了 science、physics 等非英语学科
- Prompt 中虽然写了"适龄性"，但没有明确指定"使用中文"
- 去重阶段才发现语言问题，修复成本高

### 改进方案

**1. 生成前：在 Prompt 中增加语言强制约束**

```
【语言约束】
- 中文学科（数学/语文/科学/物理/化学/生物/历史/地理/政治）的所有字段必须使用中文
- 包括：content、options.text、explanation、tags
- 仅 english 学科允许使用英文
- 任何情况下不得混合中英文（如选项中既有中文又有英文）
```

**2. 生成后：增加语言检测流水线**

```python
def check_language(question, subject):
    if subject != 'english':
        # 检测 content 是否以英文字母开头
        if re.match(r'^[A-Za-z]', question['content']):
            return False, "非英语学科题目使用了英文"
    return True, "OK"
```

**3. 字段级校验**

| 字段 | 校验规则 |
|------|----------|
| content | 非英语学科：不得以英文字母开头 |
| options | 非英语学科：选项文本必须为中文 |
| explanation | 非英语学科：解析必须为中文，且长度 >= 50 字 |
| tags | 非英语学科：标签必须为中文 |

## 三、难度评估：从"生成时自评"改为"后验验证 + 动态调整"

### 当前问题
- difficulty 是生成时由 AI 自行指定的，缺乏客观验证
- 实际执行中发现大量题目 difficulty 标签不准确
- 没有基于用户答题数据的难度校准机制

### 改进方案

**1. 增加 DifficultyEvaluatorAgent（后验评估）**

```
生成题目 → QualityCheckAgent（快检） → DifficultyEvaluatorAgent（后验评估） → 入库
```

- DifficultyEvaluatorAgent 根据以下维度独立评估难度：
  - 知识点数量（1个/2-3个/3个以上）
  - 计算/推理步骤数
  - 信息提取复杂度
  - 概念抽象度
- 评估结果与生成时自评对比，差异超过 1 级则标记为"难度争议"

**2. 引入用户答题数据统计**

```sql
-- 每道题的难度校准表
CREATE TABLE question_difficulty_stats (
    question_id UUID PRIMARY KEY,
    total_attempts INT DEFAULT 0,
    correct_count INT DEFAULT 0,
    correct_rate DECIMAL(5,2),  -- 正确率
    avg_time_seconds INT,        -- 平均答题时间
    calibrated_difficulty VARCHAR(20),  -- 基于数据的校准难度
    last_updated TIMESTAMP
);
```

- 正确率 > 80% → 降级为 beginner
- 正确率 60%-80% → 保持 intermediate
- 正确率 < 60% → 升级为 advanced
- 每 100 次答题后自动校准一次

**3. 难度标签双轨制**

| 字段 | 含义 | 来源 |
|------|------|------|
| `difficulty` | 预设难度（beginner/intermediate/advanced） | 生成时指定 |
| `calibrated_difficulty` | 校准难度 | 基于用户答题数据统计 |
| `display_difficulty` | 展示给用户看到的难度 | 优先使用 calibrated，数据不足时 fallback 到 difficulty |

## 四、去重机制：从"文本匹配"升级为"语义指纹"

### 当前问题
- 仅基于 `content + correct_answer` 字符串匹配去重
- 同义变换题（如"小明有5个苹果"和"小红有5个苹果"）被视为不同题目
- 去重后仍残留大量语义重复题

### 改进方案

**1. 增加知识点指纹（Knowledge Fingerprint）**

```json
{
  "knowledge_fingerprint": {
    "subject": "math",
    "age_group": "13-15",
    "knowledge_points": ["一元二次方程", "判别式", "根的性质"],
    "question_type": "single_choice",
    "cognitive_level": "应用",  // 识记/理解/应用/分析/评价/创造
    "template_id": "quad_eq_delta_001"  // 对应种子题库模板ID
  }
}
```

**2. 多级去重策略**

| 级别 | 方法 | 去重粒度 |
|------|------|----------|
| L1 | 精确文本匹配 | 完全相同的题目 |
| L2 | 知识点指纹匹配 | 同一知识点 + 同一题型 + 同一认知层级 |
| L3 | 语义相似度（SimHash/MinHash） | 表述不同但解题思路相同的题目 |
| L4 | 人工抽检 | 保留变式题（数字不同但思路相同），去除纯重复题 |

**3. 变式题识别规则**

```python
def is_variant(q1, q2):
    """判断两道题是否为变式题（应保留）"""
    # 知识点指纹相同
    if q1['knowledge_fingerprint'] != q2['knowledge_fingerprint']:
        return False
    # 正确答案不同（数字/答案不同）
    if q1['correct_answer'] == q2['correct_answer']:
        return False
    # 题干相似度 < 90%（表述有明显差异）
    if similarity(q1['content'], q2['content']) > 0.9:
        return False
    return True  # 是变式题，保留
```

## 五、数据质量：增加生成后强制校验流水线

### 当前问题
- 212 道题 content 过短或 explanation 为空
- 433 道题 difficulty 字段使用中文值（简单/中等/困难）而非标准英文值
- 部分题目 options 格式不统一（有的是字符串数组，有的是对象数组）

### 改进方案

**1. 增加 QualityGate（质量门禁）**

每批题目生成后，必须通过以下校验才能进入下一环节：

```python
QUALITY_RULES = [
    # 字段非空检查
    lambda q: q['content'] and len(q['content']) > 5,
    lambda q: q['correct_answer'] and len(str(q['correct_answer'])) > 0,
    lambda q: q['explanation'] and len(q['explanation']) >= 50,
    
    # 字段值域检查
    lambda q: q['difficulty'] in ['beginner', 'intermediate', 'advanced'],
    lambda q: q['type'] in ['single_choice', 'multiple_choice', 'fill_blank', 'true_false', 'short_answer'],
    
    # 语言检查
    lambda q: check_language(q, q['subject'])[0],
    
    # 选项检查
    lambda q: q['type'] in ['fill_blank', 'short_answer'] or (q['options'] and len(q['options']) >= 2),
    
    # 适龄性检查
    lambda q: len(q['content']) <= MAX_CONTENT_LENGTH[q['age_group']],
]
```

**2. 自动修复 vs 人工确认**

| 问题类型 | 处理方式 | 示例 |
|----------|----------|------|
| explanation 过短 | 自动重新生成 | AI 重新写解析 |
| difficulty 中文值 | 自动映射转换 | "简单" → "beginner" |
| content 为空 | 自动丢弃并重新生成 | 删除该题，补充新题 |
| 语言错误 | 自动丢弃并重新生成 | 删除英文题，补充中文题 |
| 答案有歧义 | 标记为"争议题"，人工确认 | 暂不入库，等待审核 |

**3. 批量质量报告**

每批次生成后输出质量报告：

```
批次：math_13-15_int_001
生成数量：70
通过质检：68
自动修复：1
丢弃：1
争议题（需人工确认）：0
通过率：97.1%
```

## 六、数据库设计：增加题目指纹和关联表

### 当前问题
- `questions` 表结构过于简单，仅有基础字段
- 缺少知识点关联、题目指纹、变式关系等关键信息
- 无法支持"错题变式"、"知识点关联推荐"等高级功能

### 改进方案

**1. 扩展 questions 表**

```sql
ALTER TABLE questions ADD COLUMN IF NOT EXISTS 
    knowledge_fingerprint JSONB,      -- 知识点指纹
    template_id VARCHAR(50),           -- 种子模板ID（变式题）
    variant_group_id UUID,             -- 变式题组ID
    cognitive_level VARCHAR(20),       -- 认知层级（识记/理解/应用/分析/评价/创造）
    estimated_difficulty DECIMAL(3,2), -- 预估难度系数（0-1）
    language VARCHAR(10) DEFAULT 'zh', -- 题目语言
    generation_source VARCHAR(20),     -- 生成来源（seed_variant/ai_generated/crawled）
    quality_score INT,                 -- 质量评分（0-100）
    review_status VARCHAR(20) DEFAULT 'pending';  -- 审核状态
```

**2. 新增知识点关联表**

```sql
CREATE TABLE knowledge_points (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    subject VARCHAR(20) NOT NULL,
    age_group VARCHAR(10) NOT NULL,
    name VARCHAR(100) NOT NULL,        -- 知识点名称
    parent_id UUID REFERENCES knowledge_points(id),  -- 父知识点（层级关系）
    difficulty_range VARCHAR(20),      -- 难度范围
    description TEXT,
    UNIQUE(subject, age_group, name)
);

CREATE TABLE question_knowledge (
    question_id UUID REFERENCES questions(id) ON DELETE CASCADE,
    knowledge_point_id UUID REFERENCES knowledge_points(id) ON DELETE CASCADE,
    is_primary BOOLEAN DEFAULT false,  -- 是否为主要知识点
    PRIMARY KEY (question_id, knowledge_point_id)
);
```

**3. 新增题目统计表（支持动态难度校准）**

```sql
CREATE TABLE question_stats (
    question_id UUID PRIMARY KEY REFERENCES questions(id) ON DELETE CASCADE,
    total_attempts INT DEFAULT 0,
    correct_count INT DEFAULT 0,
    correct_rate DECIMAL(5,2),
    avg_time_seconds INT,
    first_seen_at TIMESTAMP,
    last_attempt_at TIMESTAMP,
    calibrated_difficulty VARCHAR(20)
);
```

## 七、爬取策略：补充具体执行方案

### 当前问题
- 方案中提到了"爬取 + 生成并行"，但没有具体的爬取目标、解析规则和版权合规检查
- 实际执行时完全跳过了爬取步骤

### 改进方案

**1. 明确爬取目标清单**

| 来源类型 | 示例 | 解析方式 | 版权风险 |
|----------|------|----------|----------|
| 公开试卷 PDF | 各地教育局公开的期末试卷 | PDF 解析（PyPDF2/pdfplumber） | 低（政府公开文件） |
| 开放题库 API | 如某些教育平台提供的开放 API | API 调用 | 中（需确认授权） |
| 公开文档 | 国家课程标准、教学大纲 | HTML/Markdown 解析 | 低 |

**2. 爬取后处理流水线**

```
爬取原始内容 → 结构化提取（题干/选项/答案/解析） → 格式标准化 → 质量检查 → 版权合规检查 → 入库
```

**3. 版权合规检查**

- 不爬取商业付费题库（如学科网 VIP 内容）
- 爬取内容需标注来源 URL
- 爬取题目标记 `source: 'crawled_<site_name>'`
- 定期审查爬取内容的版权状态

## 八、验收标准：从"数量达标"升级为"质量指标"

### 当前问题
- 验收仅检查总题量是否 >= 5460
- 没有质量指标（重复率、合格率、语言一致性率等）
- 没有长期可追踪的指标（用户正确率分布、难度校准准确率等）

### 改进方案

**1. 生成阶段验收指标**

| 指标 | 目标值 | 当前值（参考） |
|------|--------|---------------|
| 总题量 | >= 5460 | 5471 |
| 去重率（去重前/去重后） | < 15% | ~22% |
| 字段完整率 | 100% | ~96% |
| 语言一致性率 | 100% | ~92% |
| 难度标签准确率 | >= 90% | 未统计 |
| 解析完整率（>=50字） | 100% | ~96% |

**2. 运行阶段监控指标**

| 指标 | 说明 |
|------|------|
| 题目平均正确率 | 各难度级别的用户正确率是否符合预期 |
| 难度校准准确率 | calibrated_difficulty 与用户实际表现的一致性 |
| 题目弃用率 | 因质量问题被用户举报或系统下架的题目比例 |
| 变式题覆盖率 | 同一知识点的变式题数量是否充足 |

## 九、执行建议优先级

| 优先级 | 改进项 | 影响 | 工作量 |
|--------|--------|------|--------|
| P0 | 增加语言强制约束 + 生成后语言检测 | 高（避免 434 道题返工） | 小 |
| P0 | 增加字段非空/值域校验（QualityGate） | 高（避免 212 道不合格题入库） | 小 |
| P1 | 建立种子题库 + 变式生成引擎 | 高（降低去重率从 22% 到 < 10%） | 中 |
| P1 | 统一 difficulty 标准值 + 映射表 | 中（避免前端颜色显示异常） | 小 |
| P2 | 增加 DifficultyEvaluatorAgent（后验评估） | 中（提高难度标签准确率） | 中 |
| P2 | 扩展 questions 表结构（指纹/统计/关联） | 高（支撑高级功能） | 中 |
| P3 | 多级去重策略（语义指纹 + SimHash） | 中（进一步降低重复率） | 大 |
| P3 | 补充爬取策略具体方案 | 低（v0.1 可暂缓） | 中 |

---

*总结：当前方案的核心问题是"生成阶段缺乏约束，导致后续修复成本高"。改进思路是"前置约束 + 后置校验 + 数据驱动优化"，从"先生成再修"转向"有控制地生成"。*
