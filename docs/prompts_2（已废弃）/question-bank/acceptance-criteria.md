# 题库生成验收标准

## 验收目标

验证题库生成系统能够稳定产出 **至少 5460 道**（基础目标 5460，可多不可少）符合质量标准的教育题目，并成功导入数据库。

---

## 一、数量验收

### 1.1 总量达标

| 检查项 | 标准 | 验收方法 |
|--------|------|----------|
| 总题量 | ≥ 5460 道 | `SELECT COUNT(*) FROM questions` |
| 小学（6-12 岁）| ≥ 1680 道 | 按 `age_group IN ('6-8', '9-12')` 统计 |
| 初中（13-15 岁）| ≥ 1890 道 | 按 `age_group = '13-15'` 统计 |
| 高中（16-18 岁）| ≥ 1890 道 | 按 `age_group = '16-18'` 统计 |

### 1.2 学科分布均匀

每个学科在每个年龄段每个难度的题目数应在 **65-75** 之间（目标 70，允许 ±5 浮动）：

```sql
SELECT subject, age_group, difficulty, COUNT(*)
FROM questions
GROUP BY subject, age_group, difficulty
HAVING COUNT(*) < 65 OR COUNT(*) > 75;
-- 期望结果：空集（无异常）
```

### 1.3 题型分布合理

每个批次（70 题）的题型分布应符合以下比例（允许 ±2 浮动）：

| 题型 | 目标数量 | 占比 |
|------|----------|------|
| single_choice | 30 | 43% |
| multiple_choice | 12 | 17% |
| fill_blank | 14 | 20% |
| true_false | 8 | 11% |
| short_answer | 6 | 9% |

## 二、质量验收

### 2.1 规范性检查（100% 通过）

每道题必须通过以下检查：

- [ ] `content` 非空且长度 > 5 个字符
- [ ] `correct_answer` 非空
- [ ] `explanation` 长度符合年龄段要求（6-8: ≥30, 9-12: ≥40, 13-15: ≥50, 16-18: ≥50 字）
- [ ] `type` 在允许列表中
- [ ] `difficulty` 在 beginner/intermediate/advanced 中
- [ ] `subject` 在允许列表中
- [ ] `age_group` 在允许列表中

**验收 SQL**：
```sql
SELECT COUNT(*) FROM questions
WHERE content IS NULL OR LENGTH(content) <= 5
   OR correct_answer IS NULL OR correct_answer = ''
   OR explanation IS NULL OR explanation = ''
   OR type NOT IN ('single_choice', 'multiple_choice', 'fill_blank', 'true_false', 'short_answer')
   OR difficulty NOT IN ('beginner', 'intermediate', 'advanced');
-- 期望结果：0
```

### 2.2 适龄性检查（≥ 95% 通过）

抽查每个学科每个年龄段 10 道题（共 4×10=40 或 9×10=90 道），人工检查：

- [ ] 题干长度符合年龄段约束
- [ ] 选项长度符合年龄段约束
- [ ] 无超纲内容
- [ ] 语言风格适合目标年龄段

**通过标准**：抽查通过率 ≥ 95%

### 2.3 准确性检查（≥ 98% 通过）

抽查每个学科每个年龄段 5 道计算题/逻辑题，人工验证：

- [ ] 正确答案确实正确
- [ ] 答案唯一
- [ ] 解析中的解题思路正确
- [ ] 无自相矛盾

**通过标准**：抽查通过率 ≥ 98%

### 2.4 干扰项质量检查（≥ 90% 通过）

抽查每个学科 10 道单选题，人工评估错误选项的干扰性：

- [ ] 错误选项不能一眼排除（需要经过思考才能判断）
- [ ] 错误选项符合至少一种干扰策略（计算错误/概念混淆/遗漏条件/逆命题/扩大范围）

**通过标准**：抽查通过率 ≥ 90%

### 2.5 安全合规检查（100% 通过）

全量扫描：

- [ ] 无暴力、恐怖、血腥内容
- [ ] 无政治敏感内容
- [ ] 无不当价值观
- [ ] 无个人隐私信息
- [ ] 英语题无中文混入

**验收方法**：关键词过滤 + 人工抽查 5%

## 三、Agent 流程验收

### 3.1 主控编排器（Master Orchestrator）

- [ ] 能将 ≥ 5460 题任务正确拆分为小批次（每批 ≤10 题）
- [ ] 能正确调度生成 Agent 和爬取 Agent 并行工作
- [ ] 质量流水线（难度评估 → 质检 → 去重）按顺序执行
- [ ] 失败重试机制正常（最多 3 次）
- [ ] 最终报告包含：生成数、通过数、失败数、重复率、知识点覆盖

### 3.2 题目生成器（Question Generator）

- [ ] 能按输入的学科/年龄/难度/知识点生成题目
- [ ] 每道题附带完整解析
- [ ] 题型分布符合要求
- [ ] 干扰项设计有策略性
- [ ] 输出格式为标准 JSON

### 3.3 难度评估器（Difficulty Evaluator）

- [ ] 对每道题给出 4 维评分（知识点/推理/信息/抽象）
- [ ] 评分有明确依据（引用题目具体条件）
- [ ] 年龄段校准已应用
- [ ] 准确率 ≥ 80% 的批次通过

### 3.4 质量检测器（Quality Checker）

- [ ] 通过 5 个维度检查（规范/准确/适龄/安全/题型）
- [ ] 安全/合规问题被严格拦截
- [ ] 通过率 ≥ 90% 的批次通过
- [ ] 失败的题目给出具体原因和修改建议

### 3.5 去重查重器（Deduplication Agent）

- [ ] 能识别精确重复题目
- [ ] 能识别语义相似题目（SimHash）
- [ ] 能识别知识点+题型+答案组合重复
- [ ] 能区分变式题和重复题
- [ ] 重复率控制在合理范围（预计 5-15%）

### 3.6 解析补充器（Explanation Supplementer）

- [ ] 能为无解析的题目补充解析
- [ ] 解析长度符合年龄段要求
- [ ] 解析说明解题思路，不只是给答案
- [ ] 能识别答案可能有误的题目并标注

### 3.7 PDF/Word 解析器（PDF Parser）

- [ ] 能从 PDF 提取文本（支持单栏/双栏）
- [ ] 能从 Word 提取文本
- [ ] 能按题号分割题目
- [ ] 能分离题干/选项/答案/解析
- [ ] 能推断题型
- [ ] 解析率 ≥ 85%

### 3.8 数据库导入器（Database Importer）

- [ ] 支持增量导入（跳过重复）
- [ ] 支持全量导入（清空后重新导入）
- [ ] 导入前进行冲突检测
- [ ] 批量导入性能正常（100 题/批次，无超时）
- [ ] 导入后数量与预期一致
- [ ] 索引已创建，查询性能正常

## 四、数据完整性验收

### 4.1 字段完整性

```sql
-- 检查各关键字段的非空率
SELECT
  AVG(CASE WHEN content IS NOT NULL THEN 1 ELSE 0 END) as content_rate,
  AVG(CASE WHEN correct_answer IS NOT NULL THEN 1 ELSE 0 END) as answer_rate,
  AVG(CASE WHEN explanation IS NOT NULL AND explanation != '' THEN 1 ELSE 0 END) as explanation_rate,
  AVG(CASE WHEN tags IS NOT NULL AND array_length(tags, 1) > 0 THEN 1 ELSE 0 END) as tags_rate
FROM questions;

-- 期望结果：所有 rate ≥ 0.95
```

### 4.2 来源追溯

- [ ] 每道题有 `source` 字段（ai_generated / crawled_xxx / open_dataset）
- [ ] 爬取的题有 `source_url` 字段
- [ ] AI 生成的题有生成批次信息

### 4.3 变式题标记

- [ ] 变式题已标记 `is_variant_of` 字段
- [ ] 变式题与原始题在同一学科同一年龄段

## 六、验收流程

```
Step 1: 数据准备
  ├── 确认 9 份 Agent 提示词已就位
  ├── 确认数据库表已创建
  └── 确认爬取目标网站可访问

Step 2: 小规模试运行
  ├── 选择 1 个学科 1 个年龄段（如：初中数学 intermediate）
  ├── 完整跑一遍 9 个 Agent 的流程
  ├── 人工抽查 20 道题
  └── 记录问题并修正提示词

Step 3: 批量执行
  ├── 按阶段 1-5 分批执行
  ├── 每阶段完成后进行质量抽检
  └── 不合格批次退回重跑

Step 4: 全量质检
  ├── 数量统计（总量 + 分布）
  ├── 规范性检查（SQL 查询）
  ├── 适龄性抽查（人工 5%）
  ├── 准确性抽查（人工 3%）
  └── 安全合规扫描（全量）

Step 5: 验收签字
  ├── 所有检查项通过
  ├── 验收报告生成
  └── 数据库备份
```

## 八、不合格处理

| 问题类型 | 处理方式 |
|----------|----------|
| 数量不足 | 补充生成/爬取，差额补足 |
| 质量不达标（通过率 < 标准）| 退回对应批次，修正后重跑 |
| Agent 流程异常 | 修正提示词，重新测试 |
| 数据入库失败 | 回滚后重新导入 |
| 安全合规问题 | 立即删除问题题目，补充生成 |
