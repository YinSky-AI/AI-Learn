# prompts_3 第二阶段实施计划

## 目标

在第一阶段的两层出题与四角色辅导稳定后，按依赖顺序补齐错题闭环、成长激励、学习报告、知识图谱、移动端 PWA、每日挑战和全局 AI 入口。

## 约束

- 出题始终只有“出题 Agent → 审题 Agent”两层；导师四角色不得参与出题。
- 对用户的失败信息必须是简短中文，不暴露堆栈或数据库细节。
- 不覆盖当前未提交的课程、题库和学习页改动。
- 每个后端模型都必须有迁移或可重复初始化策略；应用代码变动后重建 Docker 并检查日志。
- 每个 UI 模块都必须在桌面与 390px 宽移动端完成真实浏览器截图验收。

## 任务与依赖

1. **错题本（06，中）**：模型、服务、API、自动收录、筛选/重练/掌握状态和页面。答错写入与答题事务一致。
2. **游戏化（07，中）**：经验、等级、连续学习与成就；消费答题与错题事件，避免重复发奖。
3. **行为模型与报告（08，中）**：记录学习事件，计算学习画像、薄弱知识点与报告；只使用授权学习数据。
4. **知识图谱（09，低）**：基于报告的掌握度提供 2–3 个学科 MVP 图谱、节点详情与练习入口。
5. **PWA 与移动端（10，中）**：manifest、图标、离线降级、安装提示、底部导航和 44px 触控目标。
6. **每日挑战与排行榜（11，中）**：挑战、尝试、服务器端计时/计分、每日一次约束、排行榜与页面。
7. **全局 AI 浮窗（12，低）**：懒加载导师面板、快捷问题、页面上下文；不遮挡移动端底栏。
8. **全量验收（高）**：容器重建、迁移、API/单元/前端构建、桌面/移动浏览器完整流程、截图和日志检查。

## 耦合检查

- 错题与挑战均引用 `questions`、`users`：先确认 UUID、外键、索引与数据库连接均为主学习库。
- 答题结果同时驱动错题、经验和行为事件：以单一服务编排、去重键和明确事务边界避免半成功或重复写入。
- 学习报告的掌握度是知识图谱唯一来源；图谱页面不可自行写入学习数据。
- PWA、底栏与浮窗共享主布局：布局变更后检查所有现有页面、z-index 与安全区。
- 挑战得分由后端计算，前端只展示；排行榜只返回必要公开信息。

## 验收门槛

- 每个任务：先测试、后实现、独立审查、提交。
- 发现 P1/P2 后先修复再进入依赖任务。
- 最终输出 Docker 状态、测试结果、错误日志检查与关键桌面/移动截图。
