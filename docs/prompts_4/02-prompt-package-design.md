# Prompts 4 优化提示词包设计

## 1. 目标

将 `docs/reviews/project-optimization-summary.html` 中的 21 项项目优化建议转换为可逐项交给编码 AI 执行的 Vibe Coding 提示词包。

提示词包只描述后续任务，不在本阶段修改业务代码。每个任务必须能够独立完成调查、设计、实施和验收，并通过统一规则控制删除、数据库迁移、接口兼容、错误处理、浏览器测试和截图证据等风险。

## 3. 总控文档职责

### README.md

- 说明提示词包来源、使用方式和适用范围。
- 提醒一次只执行一个任务，不允许把 21 个提示词同时交给 AI。
- 提供 P0、P1、P2 导航和执行进度清单。
- 区分“提示词已编写”和“功能已实施”，避免将计划误认为现状。

### 00-global-execution-rules.md

所有任务共同遵守以下规则：

- 修改前读取最新文件和项目级指令。
- 先调查、再设计、再实施，禁止基于 HTML 中的旧行号盲改。
- 不删除文件、模块、数据、容器或数据库，除非先完成引用检查并取得明确授权。
- 数据结构、ORM、Schema、API DTO、前端类型和展示必须同步检查。
- 面向用户的错误必须为清晰纯文本，不得暴露异常堆栈、SQL、密钥或内部对象。
- 功能或错误修复使用红—绿—重构流程，并补充真实行为测试。
- 修改应用代码后重建镜像；仅修改文档时不得无意义重建。
- UI 任务必须使用内部浏览器完成真实操作、控制台检查、响应式检查和截图验收。
- 数据库任务必须提供备份、迁移、回滚与恢复验证证据。
- 完成前运行与风险匹配的测试、构建、日志、健康检查和 Git 范围审计。

### 01-implementation-order.md

采用依赖驱动顺序，而不是机械按照报告编号执行：

1. 建立交付验收基线。
2. 建立备份和恢复能力。
3. 建立可追溯 Schema 迁移。
4. 修复答案泄露和管理后台认证。
5. 完善管理变更保护和账号主体校验。
6. 统一学习维度、题库访问与答题事务。
7. 完善运行就绪、流量预算和诊断链路。
8. 完善生成任务和学习调度。
9. 重构前端练习、辅导、契约与可用性状态。
10. 在有测量基线后处理查询性能、后台模块和数据治理。

文档同时标注并行限制：数据库迁移、认证、答题事务及跨数据库题库访问不得并行修改共享模型或配置。

## 4. 单项任务提示词模板

每个任务文件必须包含以下内容，不能只复述 HTML：

1. **任务定位**：优先级、风险等级、目标和非目标。
2. **当前证据**：报告中的问题、影响、候选文件和需要重新验证的假设。
3. **开始前调查**：要求 AI 阅读真实代码、测试、配置、Git 状态和关联调用链。
4. **允许修改范围**：本任务可能涉及的模块和允许新增的测试或迁移。
5. **禁止操作**：不相关重构、删除、硬编码密钥、吞异常、用 mock 代替真实验收等。
6. **分阶段执行**：调查 → 设计 → 测试先行 → 最小实施 → 自主验收。
7. **跨模块耦合检查**：数据层、ORM、API、前端、网关、Docker、环境变量和多数据库连接。
8. **错误处理要求**：日志上下文、用户友好错误、敏感信息脱敏和失败回滚。
9. **验收标准**：按任务定制可观测、可执行、可判定的检查项。
10. **最终报告格式**：修改文件、设计决策、命令结果、截图、日志、残余风险和人工步骤。

## 5. 任务差异化要求

- 安全任务必须包含未授权、过期、撤销、CSRF、越权和敏感信息回归测试。
- 数据库任务必须使用独立测试数据库，验证 upgrade、downgrade 或恢复路径，不得在唯一数据副本上试验。
- 并发与事务任务必须包含幂等、重复请求、并发写入和部分失败测试。
- AI 任务保持“出题 Agent + 审题 Agent”两层约束，不恢复 `prompts_2` 的复杂多层出题架构。
- 前端任务必须覆盖 loading、empty、error、offline、重试、键盘操作和移动端视口。
- 性能任务必须先建立查询数、延迟或资源基线，禁止无测量引入全局缓存。
- 数据治理任务先要求确认适用地区、用户年龄和真实合规要求，不让编码 AI 自行给出法律结论。

## 6. 验收设计

提示词包生成后进行以下静态验收：

- 文件数量与清单一致：3 个总控文档、1 个设计说明、21 个任务提示词。
- 优先级分布一致：P0 为 8 个、P1 为 9 个、P2 为 4 个。
- 每个任务均包含统一模板的 10 类内容。
- 每项 HTML 建议恰好映射到一个任务文件，无重复、无遗漏。
- 每个任务均含有任务特有的验收条件，而不是复制通用模板。
- 所有内部 Markdown 链接有效。
- `docs/INDEX.md` 能导航到 `prompts_4/README.md`。
- Git 变更仅限 `docs/**/*.md`，`git diff --check` 通过。

## 7. 边界

本次只创建和更新 Markdown 文档：

- 不修改后端、前端、Docker、数据库或 CI 配置。
- 不执行 21 项优化功能。
- 不删除现有提示词或历史文档。
- 不将 HTML 中的候选行号视为永久事实；每个提示词要求执行时重新核对代码。
- 不在提示词中写死云数据库密码、API Key 或真实用户数据。

## 8. 完成定义

当 21 项建议全部映射为独立提示词、总控规则和依赖顺序完整、索引可导航、静态检查通过且 Git 变更范围仅为 Markdown 时，本次提示词包拆分完成。
