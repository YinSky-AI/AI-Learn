# P0-01：题目访问隔离（Question Access）

将本文件完整交给编码 AI 执行。你必须先调查当前代码再做设计和实现；HTML 报告的文件与行号只是待核验证据，不能直接当作现状。严格遵守项目 `AGENTS.md` 与 [全局执行规则](../00-global-execution-rules.md)。

## 任务定位

- 优先级：P0；风险：高（题库答案泄露）。目标是建立唯一的题目访问策略：公开场景只返回不含答案和解析的 `QuestionBrief`，完整题目仅在已验证作答流程或管理员 Adapter 中按最小权限使用。
- 非目标：不重建题库、不过度拆分服务、不改变已确认的业务计分规则，也不恢复 `prompts_2` 的复杂多层出题架构。
- 任何涉及 AI 题目生成或审查的既有链路必须继续保留“出题 Agent + 审题 Agent”两层约束。

## 当前证据

- Finding 1 的候选证据为 `backend/app/api/v1/content.py:162-245`、`schemas/content.py:114-132`、`services/content_service.py:497-509`：匿名题目列表疑似使用含 `correct_answer` 和解析的完整响应形状。
- 影响是可批量枚举答案、破坏测验公平性并泄露题库资产。建议边界是由 Question Access Policy 决定公开 `QuestionBrief` 与已验证/管理员 `Full` Adapter；收益是答案披露规则集中、一处修复覆盖所有入口。
- 先在当前代码中逐一重新核验端点、DTO、序列化、缓存、前端调用和测试；记录已不成立的假设，不得因旧行号盲改。

## 开始前调查

1. 阅读项目和目录级 `AGENTS.md`、当前 `git status`、相关 API/服务/Schema/模型、前端类型与调用链、认证依赖、测试、配置和路由。
2. 全局搜索 `correct_answer`、解析字段、题目响应模型及所有公开/练习/管理/AI 导出入口，明确每个消费者需要 Brief 还是 Full。
3. 写出最小 DTO 与访问策略设计，确认已验证作答的主体、所有权与管理员授权语义；如果缺少明确业务规则，停止并请求澄清。

## 允许修改范围

- 仅限实现该访问边界所需的题目 API、DTO/Schema、内容服务或访问策略、认证依赖、调用方适配和对应单元/集成/端到端测试。
- 可新增小型、具名的访问策略或 Adapter；接口若需演进，保持公开消费者兼容或提供明确迁移路径。
- 不在本任务中修改数据库结构、Docker 编排、无关学习流程或交付流水线。

## 禁止操作

- 禁止把完整题目 DTO 直接复用于公开列表、以“前端不展示”代替服务端隔离，或让客户端字段过滤成为安全边界。
- 禁止删除题目、答案、历史数据或模块；删除前必须全局引用检查并取得用户明确授权。
- 禁止硬编码/输出令牌、密钥、真实数据，吞掉授权异常，或用 mock 取代真实 HTTP 响应验收。

## 分阶段执行

1. 调查：完成证据复核、消费者矩阵和可修改文件清单，检查 P0-01 不与 P0-02、P0-05、P0-06 并行编辑共享认证/题库资源。
2. 设计：定义 Brief/Full 的字段边界、访问决策与兼容方案；先取得必要授权再扩大范围。
3. 测试先行：先写失败的公开 DTO、已验证作答、管理员授权和越权回归测试。
4. 最小实施：在单一访问边界实施策略，适配合法调用方，保留“出题 Agent + 审题 Agent”约束。
5. 自主验收：运行测试、相关构建和真实接口检查；若代码变更运行容器，按规则重建并检查日志/健康状态。

## 跨模块耦合检查

- 检查题目模型、ORM、Schema/DTO、服务、API 路由、认证/授权、前端类型和展示是否一致；公开响应不得因缓存、导出或其他路由重新泄露答案。
- 核对题库数据库与主库的 Session、连接串和路由，确保 A 库 API 不会误连 B 库；确认网关、环境变量和 Docker 没有隐性影响。
- 评估对阶段 9 前端契约任务的影响，并记录任何响应形状变化。

## 错误处理要求

- 对未认证、未授权、题目不存在和所有权失败返回清晰纯文本/既定安全错误契约，不返回答案、解析、SQL、堆栈、对象字符串或敏感上下文。
- 为访问拒绝和关键策略分支记录可关联、脱敏的结构化日志；对象型异常提取 `message`，不得直接 `str()` 暴露内部细节。
- 任何失败实施应可回退到上一个已验证版本；不得通过临时绕过授权完成发布。

## 验收标准

- 真实 HTTP/API 集成测试证明匿名/普通公开请求的每一种题目响应都不含 `correct_answer`、解析及等价泄露字段，且对嵌套、列表、分页和缓存响应做字段断言。
- 已验证作答流程仅在服务端确有必要时取得 Full，管理员 Full 入口同时验证会话、权限和审计；越权、过期或撤销身份均不能读取答案。
- 前端公开路径按新公开 DTO 正常渲染，合法练习/管理路径不回归；测试覆盖所有已调查入口而非只覆盖一个端点。
- 相关测试、构建、日志/健康检查、`git diff --check`、`git diff`、`git status` 均通过；报告含命令结果与必要截图（若 UI 实际变更）。

## 最终报告格式

按固定顺序报告：1) 状态与目标；2) 实际修改文件和 Brief/Full 设计；3) 对 Finding 1 的重新验证结论；4) 测试、构建、真实接口、日志、健康和 Git 审计命令及结果；5) 数据库证据（如适用）；6) 内部浏览器操作、控制台/响应式检查与截图路径（如 UI 变更）；7) 提交 SHA；8) 残余风险、兼容性限制和需人工执行步骤。报告不得包含密钥或真实用户数据。
