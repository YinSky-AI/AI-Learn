# P0-03：可恢复的管理变更（Administrative Change）

将本文件完整交给编码 AI 执行。必须先重查当前代码和业务规则；报告候选行号不是可直接修改的事实。全程遵守 `AGENTS.md`、全局执行规则，并保持“出题 Agent + 审题 Agent”两层约束。

## 任务定位

- 优先级：P0；风险：极高（后台物理删除及级联损失）。目标是让管理变更默认可恢复：停用/软删除、记录操作者/原因/影响范围/前后值，并把物理清理设为延迟且受控的操作。
- 非目标：未经授权不删除或迁移历史数据；不在本任务扩展为完整后台重构或数据治理项目。

## 当前证据

- Finding 3 候选证据为 `backend/app/admin/routes.py:474-512,704-739,1114-1159,1613-1642` 和 `models/* ondelete=CASCADE`。用户、课程、课时、题目疑似物理删除并跨表级联，且没有持久化管理员审计。
- 影响是误操作可能永久清除学习进度、作答、聊天、错题与积分，无法追责。建议为默认停用/软删除、审计前后值和延迟物理清理；收益是全后台领域共享可恢复策略。
- 必须逐个核验模型级联、路由、服务、数据库约束、现有审计、恢复需求和真实保留期。

## 开始前调查

1. 阅读管理路由、模型、外键/级联、服务、迁移、审计/日志、认证依赖、测试、数据库连接与 `git status`。
2. 全局搜索 `delete`、`ondelete=CASCADE`、批量删除、管理表单、后台任务和关联数据（进度、作答、聊天、错题、积分），形成影响图和可恢复状态定义。
3. 先核验并记录数据库目标 `host`、`database`、`environment`；涉及数据/Schema 前确认已有备份，且仅在独立可丢弃测试数据库演练。生产清理、历史数据回填或保留期取舍必须取得明确授权。

## 允许修改范围

- 可修改所需模型/Schema/迁移、管理服务/路由/模板、审计持久化、恢复入口和真实行为测试；可新增最小审计与软删除模块。
- 仅在已批准、可回滚迁移下调整外键或级联；保留现有数据与兼容读取语义。
- 不修改无关认证实现（只消费 P0-02 的身份上下文）、题库访问或前端学习功能。

## 禁止操作

- 禁止对未验证目标执行删除、清库、级联试验、`DROP` 或不可逆迁移；禁止在唯一数据副本上测试。
- 禁止把“软删除”只做前端隐藏，或不审计操作者/原因/影响范围；禁止吞掉跨表失败。
- 禁止把审计中的个人数据、密钥、令牌或完整敏感前后值写入用户可见错误、日志或截图。

## 分阶段执行

1. 调查：完成关联影响图和授权边界，确认 P0-02 认证及 P0-03 管理路由不会被并行改写。
2. 设计：提出状态字段、默认查询过滤、恢复窗口、审计事件/脱敏规则、物理清理审批与回滚方案；先由负责人确认高风险选择。
3. 测试先行：写入失败测试，覆盖软删除、恢复、级联保护、审计完整性、无权限/CSRF、重复操作和部分失败回滚。
4. 最小实施：在事务中实施管理变更和审计，执行经批准的迁移，并只在隔离数据库验证 upgrade/downgrade/恢复路径。
5. 自主验收：真实后台操作恢复演练、API/浏览器测试、审计查询、日志/健康和 Docker 检查；失败则修复后重跑。

## 跨模块耦合检查

- 检查数据层、ORM、迁移、DTO、服务、管理路由/模板、后台任务、查询默认过滤和前端展示一致性。
- 对每一个关联域验证：停用主体不会误清进度/作答/聊天/错题/积分；恢复后关系与读模型可用；物理清理不会绕过审计与授权。
- 核对 P0-02 身份/CSRF/权限、主库/题库连接、Docker/环境变量及阶段 9 前端契约影响。

## 错误处理要求

- 对不可恢复风险、无权限、状态冲突、恢复失败和目标不存在提供清晰纯文本提示，不暴露 SQL、堆栈、对象或敏感审计内容。
- 日志和审计使用关联 ID，保存必要的操作者、原因、目标、影响计数和脱敏前后摘要；对象异常仅提取 `message`。
- 所有多表变更必须事务化；失败自动回滚并留下可诊断但脱敏的记录。

## 验收标准

- 隔离数据库中的真实恢复演练证明：删除请求默认进入可恢复状态，关联学习数据仍存在；授权恢复后查询与业务路径恢复正常。
- 物理清理不能由普通管理流触发，须有目标验证、明确授权、备份和可审计的延迟执行路径；测试验证失败不会产生部分级联损失。
- 每次成功/拒绝的管理变更均有操作者、原因、影响范围、前后摘要和时间的持久化脱敏审计；未授权、CSRF、越权及重复请求均被拒绝或幂等处理。
- 通过迁移 upgrade/downgrade（若适用）、单元/集成/浏览器测试、日志/健康、`git diff --check` 与 Git 范围审计，并保存 UI 截图证据。

## 最终报告格式

依序报告状态与目标、修改文件和软删除/审计设计、Finding 3 复核、测试/迁移/隔离恢复/浏览器/容器/日志/Git 命令结果、目标数据库与备份证据、截图路径、提交 SHA、残余风险和必须由授权人员执行的物理清理步骤；全程脱敏。
