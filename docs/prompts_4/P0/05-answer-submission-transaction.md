# P0-05：答题提交事务（Answer Submission Transaction）

将本文件完整交给编码 AI 执行。先基于当前代码调查和测试，再以最小改动实现；报告行号只作证据线索。遵守 `AGENTS.md` 和全局规则，并保持“出题 Agent + 审题 Agent”两层 AI 约束。

## 任务定位

- 本任务同时受 [全局执行规则](../00-global-execution-rules.md) 约束；如与本任务具体要求冲突，以全局规则为准。

- 优先级：P0；风险：高（并发写入造成学习状态静默错误）。目标是用单一事务实现集中答题提交，包含显式所有权、幂等、行锁或原子更新、回滚和一致反馈。
- 非目标：不在本任务重做前端练习状态机或复习算法；不更改题库公开访问边界；不以重试掩盖数据竞争。

## 当前证据

- Finding 5 候选文件为 `backend/app/services/learning_service.py:153-283`、`behavior_service.py`、`gamification_service.py`、`wrong_book_service.py`。一次作答会修改多份状态，但计数/JSONB 疑似无锁读后写，提交所有权隐含。
- 影响是并发提交可能丢失会话计数、积分、连胜或行为画像。建议在一个事务 Implementation 集中幂等、锁/原子更新与显式回滚；收益是调用方一次提交即获得一致性。
- 必须重查当前 API、模型、Session 边界、外键、JSONB 更新、事务装饰器、队列/副作用、前端重试和已有测试。

## 开始前调查

1. 阅读学习、行为、积分、错题服务和模型、提交 API/DTO、数据库 Session/连接、异常处理、前端调用、测试、配置及 `git status`。
2. 绘制作答写入图，确定所有权、幂等键来源和每个状态写入顺序；全局搜索所有提交入口、重试机制、计数和 JSONB 更新。
3. 在任何数据库测试/迁移前验证并记录 `host`、`database`、`environment`；使用独立可丢弃测试数据库，先备份且不得对唯一副本做并发实验。

## 允许修改范围

- 可修改提交 API/DTO、学习/行为/积分/错题服务、事务边界、模型/迁移（确实需要时）、前端调用适配和单元/集成/并发测试。
- 可新增小型提交事务协调器、幂等记录或原子仓储接口；响应变化须保持兼容或有明确迁移方案。
- 不改认证基础设施、题库目录/多数据库配置、无关生成/复习功能。

## 禁止操作

- 禁止跨多个独立提交写入关键状态、以客户端“只点一次”保证幂等、用 mock 代替真实数据库并发测试，或静默吞掉部分失败。
- 禁止在未验证的数据库目标执行清库、删除、`DROP`、不可逆迁移；禁止删除学习历史。
- 禁止把答案、令牌、个人数据、SQL、堆栈或内部对象回传给用户或写入非脱敏日志。

## 分阶段执行

1. 调查：复核所有写路径与竞争点，确认不与 P0-04/P0-06/P0-07 并行编辑学习模型、数据库连接或事务配置。
2. 设计：定义事务边界、锁/原子操作、幂等键、重复响应、所有权、失败语义和回滚；评审对前端契约的影响。
3. 测试先行：写真实数据库失败测试，覆盖重复请求、并发写入、并发不同答案、部分服务失败、所有权越界和回滚。
4. 最小实施：在一个事务中完成必要状态修改，接入受控副作用与幂等；若迁移必需，隔离验证 upgrade/downgrade。
5. 自主验收：并发压力测试、API/前端真实流程、日志/健康检查；应用改动重建容器并检查 Docker 状态。

## 跨模块耦合检查

- 同步检查学习/错题/积分/行为模型、ORM、Schema/迁移、API DTO、前端提交/重试、事件副作用、路由、日志与异常映射。
- 核对主库和题库连接、Session 生命周期及事务是否同库；禁止 A 库 API 误连 B 库或跨库伪事务。
- 检查 P0-01 的答案读取权限、P0-06 的 canonical dimensions 和阶段 9 契约任务，确保返回的反馈不泄露答案或产生形状漂移。

## 错误处理要求

- 幂等冲突、所有权失败、事务冲突、验证失败和内部失败均返回清晰纯文本/安全契约；不暴露 SQL、堆栈、JSON 对象、答案或敏感标识。
- 日志为每次提交记录脱敏请求关联 ID、幂等结果、事务阶段和回滚原因；对象异常只取 `message`。
- 任何步骤失败必须完整回滚关键状态；外部副作用用可重试/补偿方案处理，不能造成“答题失败但积分已加”。

## 验收标准

- 真实数据库集成测试证明同一幂等键的重复请求不重复计数/积分/错题/行为写入，并返回稳定、兼容的结果。
- 并发测试证明同一会话/用户的竞态不会丢失计数或产生重复奖励；不同用户/会话不会相互污染；所有权越界被拒绝。
- 注入任一中间步骤失败时，断言所有关键写入回滚，且日志含脱敏关联证据；成功路径的反馈与 API/前端契约一致。
- 完成单元、集成、并发、构建、真实 API（及 UI 若变更）、容器/健康/日志、`git diff --check` 和 Git 审计。

## 最终报告格式

依次报告状态与目标；修改文件和事务/幂等设计；Finding 5 复核；目标数据库与备份/隔离测试证据；测试、构建、API/UI、容器、日志和 Git 命令结果；截图路径（如有）；提交 SHA；残余并发风险、性能取舍和需人工执行步骤。
