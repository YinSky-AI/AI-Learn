# P0-06：学习维度与题库目录（Learning Dimensions & Question Catalog）

将本文件完整交给编码 AI 执行。HTML 证据必须在当前仓库重验，禁止依据旧行号直接改动。遵守 `AGENTS.md`、全局规则，且所有 AI 链路继续执行“出题 Agent + 审题 Agent”两层约束。

## 任务定位

- 优先级：P0；风险：高（领域值错配与多数据库误路由）。目标是建立 canonical learning dimensions，并通过题库访问 Seam 隔离主库与题库数据库 Adapter，去除存储拓扑向领域/API 泄露。
- 非目标：不合并或删除数据库，不在本任务实现大规模题库迁移，不改变题目访问安全策略或答题事务。

## 当前证据

- Finding 6 候选文件包括 `backend/app/services/content_service.py`、`auth_service.py`、`core/database.py`、`admin/routes.py`、`models/learning.py`。年龄/难度疑似有多套编码，主库/题库 Session 与配置重复，`local_only` 泄露拓扑。
- 影响是筛选错配、字段长度错误及 A 库 API 连接 B 库风险。建议建立统一学习维度和题库访问 Seam；收益是领域词汇、数据库拓扑和外部格式各自集中。
- 必须重查所有年龄、年级、难度、科目、地区等值来源/持久化/API/前端映射，及全部 Engine/Session/连接串/依赖注入。

## 开始前调查

1. 阅读领域模型、DTO、服务、内容/认证/管理路由、数据库配置、依赖注入、迁移、前端类型/筛选和测试及 `git status`。
2. 全局搜索每个学习维度的枚举、字面量、长度约束、转换器、`local_only`、Session/Engine factory 和连接串，绘制 canonical 值与消费者矩阵。
3. 在连接或写入前验证并记录每个数据库目标的 `host`、`database`、`environment` 和职责；任何数据修正、Schema 迁移或合并策略先备份，在独立测试库验证，并要求用户授权。

## 允许修改范围

- 可修改学习维度模型/DTO/验证器/映射、内容和题库访问服务、依赖注入/数据库 Adapter、相关路由/前端适配以及真实测试。
- 仅在有经过批准的迁移、备份与隔离验证时新增约束/数据转换；可新增明确命名的 catalog port/adapter。
- 不删除旧值/数据库/配置，不在同一任务重做 P0-01 的公开答案策略、P0-05 事务或认证机制。

## 禁止操作

- 禁止把 storage flag（如 `local_only`）继续暴露为领域或公开 API 语义，禁止由调用方随意选择数据库，禁止共享 Session 导致跨库写入。
- 禁止未经目标验证执行数据库写入/迁移/删除，禁止在唯一副本测试；禁止硬编码连接串或输出密钥/真实数据。
- 禁止仅批量替换字符串而未审查历史数据、接口兼容、前端选项和 AI 题目生成/审题约束。

## 分阶段执行

1. 调查：验证 Finding 6，产出值映射、数据库职责和调用图；协调 P0-01/P0-04/P0-05/P0-07，避免并行编辑共享模型/配置。
2. 设计：定义 canonical 值、边界转换、未知/废弃值处理、catalog port 与 primary/bank Adapter 路由规则；确认兼容与回滚。
3. 测试先行：为每个 canonical 值、旧值兼容/拒绝、字段长度、DTO 映射、primary/bank 路由和错误目标保护写测试。
4. 最小实施：将转换和路由集中在边界，适配消费者；若需迁移，仅在隔离库验证 upgrade/downgrade/回滚。
5. 自主验收：真实多数据库路由测试、API/前端筛选流程、日志/健康、构建和容器检查；失败即修复重验。

## 跨模块耦合检查

- 同步检查模型、ORM、Schema、迁移、服务、API DTO、前端类型/展示/筛选、管理员输入、AI 出题与审题输入输出。
- 对每条题库路径断言只使用预期 Adapter/连接，不把主库请求送往题库或反向误连；检查 Docker、环境变量、网关和测试 fixture 也遵循相同拓扑。
- 评估对 P0-01 题目 DTO、P0-05 提交反馈和阶段 9 前端契约的兼容性。

## 错误处理要求

- 无效/未知维度、目录不存在、路由配置错误或数据库不可用返回清晰纯文本/安全契约，不暴露连接串、SQL、堆栈、对象或题库答案。
- 对转换、路由和写入记录脱敏的结构化上下文（请求关联 ID、Adapter 名称、canonical 值）；对象异常只提取 `message`。
- 迁移/写入失败必须回滚，且保留旧的已验证读路径或清晰的受控回滚步骤。

## 验收标准

- 测试枚举所有 canonical 值及边界值，证明模型、API DTO、前端筛选与持久化使用相同语义，旧值按已批准策略兼容、迁移或被明确拒绝。
- 多数据库集成测试使用可辨认的隔离 fixture，断言每个 catalog/read/write 请求命中正确的 primary 或 question-bank Adapter，且绝不跨库误写。
- 真实 API 和受影响前端流程验证筛选/展示正常；AI 相关测试确认仍通过“出题 Agent + 审题 Agent”两层校验。
- 通过迁移验证（如适用）、测试、构建、日志/健康、容器状态、`git diff --check` 和 Git 审计。

## 最终报告格式

按顺序报告状态与目标；修改文件及 canonical/Adapter 设计；Finding 6 复核；数据库目标/备份/隔离迁移证据（如适用）；值映射、多数据库路由、API/UI、构建、容器、日志和 Git 命令结果；截图路径；提交 SHA；残余数据兼容风险和需人工授权的迁移步骤。
