# P0-08：交付验证基线（Delivery Verification）

将本文件完整交给编码 AI 执行。这是所有 P0 的第一阶段：先建立可重复、真实的本地与 CI 验证入口，再交付后续风险改动。先调查当前项目；HTML 证据与行号均需重新核验。遵守 `AGENTS.md` 和全局规则，并保持“出题 Agent + 审题 Agent”两层约束。

## 任务定位

- 优先级：P0；风险：高（无可靠交付证据）。目标是建立统一的后端、前端、契约、浏览器、无障碍、PWA、迁移和 Docker smoke 验证基线，并让本地与 CI 成为两个真实 Adapter。
- 非目标：不将源码字符串/正则匹配伪装为行为测试，不在本任务实现其他 P0 业务修复，不为了绿灯删除失败测试或降低安全门槛。

## 当前证据

- Finding 8 候选证据为缺少 `.github/workflows`、`frontend/package.json`、`frontend/tests/*.test.mjs`、`playwright.config.ts` 和 `Makefile`。项目疑似没有 CI，前端缺少正式 test/typecheck/e2e 命令，核心测试大量匹配源码字符串。
- 影响是不能证明真实用户旅程、接口契约、离线和容器部署在每次提交仍正常。建议统一后端、类型、构建、契约、浏览器、无障碍、PWA、迁移和 Docker smoke；收益是本地/CI 共享可复现交付证据。
- 必须重新核验现有工作流、脚本、测试质量、后端/前端构建、容器服务、浏览器测试、PWA/service worker 与制品输出。

## 开始前调查

1. 阅读 `AGENTS.md`、`git status`、后端/前端 package 配置、测试、类型检查、构建、Playwright 配置、Makefile、Docker/compose、迁移命令、PWA 资源和已有 CI。
2. 运行现有安全只读检查建立基线，记录每项命令的可用性、耗时、失败原因及哪些测试仅检查源码字符串而非用户行为。
3. 制定最小验证矩阵：后端单元/集成、前端 typecheck/test/build、契约、真实浏览器、可访问性、PWA/offline、迁移、Docker smoke、日志/健康与制品；外部 CI 凭据、服务和预算变更须获得授权。

## 允许修改范围

- 可修改/新增 CI workflow、Makefile 或任务脚本、测试配置、真实行为/契约/浏览器测试、最小测试 fixture、PWA 验收、Docker smoke 脚本和制品上传配置。
- 可把源码字符串测试替换为同等或更强的真实行为测试；新增脚本不得硬编码秘密、生产 URL 或真实用户数据。
- 不修改业务功能、数据库 Schema（只调用受控隔离迁移检查）、认证规则或无关部署架构。

## 禁止操作

- 禁止仅检查源码文本、快照或 mock 就声称浏览器/契约/PWA/Docker 已验证；禁止通过 `continue-on-error`、跳过失败或降低断言取得绿灯。
- 禁止在 CI 日志、制品、截图或仓库写入令牌、密码、连接串、真实用户数据；禁止在未验证环境执行会破坏数据的迁移/清理。
- 禁止无意义重建：仅文档变更不重建；本任务实际修改应用/编排时才按规则重建或 `up -d`。

## 分阶段执行

1. 调查：复核 Finding 8 和现有命令，建立失败/覆盖缺口清单；此 P0-08 必须先于其他 P0 作为交付门槛。
2. 设计：定义可在本地和 CI 一致运行的分层矩阵、依赖服务、超时、隔离 fixture、失败制品和最小阻断策略。
3. 测试先行：先为真实 API 契约、关键浏览器旅程、PWA/offline、Docker/health 与迁移检查编写会失败的测试。
4. 最小实施：接线正式脚本与 CI，替换弱测试，确保失败时保留可诊断制品和脱敏日志。
5. 自主验收：从干净环境实际运行全矩阵，使用内部浏览器完成真实操作、控制台和响应式检查并保存截图；修复失败后重跑。

## 跨模块耦合检查

- 检查后端 API/DTO、前端类型/构建、契约 fixture、路由/网关、环境变量、Docker/compose、数据库迁移及主库/题库连接的测试隔离。
- 验证 CI 与本地使用相同命令和有意不同的 Adapter 配置；两者都需验证“出题 Agent + 审题 Agent”链路仍受两层约束（若该链路在测试范围内）。
- PWA/Service Worker、浏览器缓存、离线响应、健康端点和制品路径不能掩盖服务失败；记录对后续 P0 任务的可复用门槛。

## 错误处理要求

- 测试/构建/部署失败输出面向执行者的清晰纯文本摘要和脱敏上下文，不泄露堆栈中的密钥、Cookie、连接串、SQL、令牌或真实数据；对象异常提取 `message`。
- 日志应按命令/测试/服务关联，保留失败截图、浏览器 trace、服务日志和构建制品；失败不得被吞掉或转换为成功。
- Docker/迁移失败先停止、验证目标和日志，再修复；保持隔离数据库可回滚，不污染共享/生产环境。

## 验收标准

- 本地和 CI 都实际运行：后端单元/集成、前端正式 test/typecheck/build、API 契约、真实浏览器 E2E、关键无障碍检查、PWA 注册/离线/更新行为、受控迁移检查、Docker build/up/smoke、健康与日志检查。
- 浏览器验收通过内部浏览器完成真实用户旅程，检查控制台、网络失败、桌面及移动视口，并保存截图/trace；测试不得主要依赖源码字符串匹配。
- Docker 验收在实际构建后检查 `docker ps`、服务健康和 Docker Desktop 错误；迁移只针对已验证的可丢弃数据库，必要时验证 upgrade/downgrade 或恢复路径。
- CI 在任一关键验证失败时明确失败并上传脱敏制品；全矩阵通过后执行 `git diff --check`、`git diff`、`git status`，审计只包含允许变更。

## 最终报告格式

按顺序报告状态与目标；修改文件和验证矩阵设计；Finding 8 复核；本地/CI 每个命令、耗时和结果；隔离数据库/迁移证据；内部浏览器操作、控制台/响应式检查、截图/trace/制品路径；Docker/健康/日志结果；提交 SHA；残余覆盖缺口、成本限制和需人工配置的 CI 秘密/服务步骤。不得在报告中包含秘密。
