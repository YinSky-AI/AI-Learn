# P1-13：生成作业（Generation Job）

将本文件完整交给编码 AI 执行。严格保持“出题 Agent + 审题 Agent”两层；不得恢复 `prompts_2` 的复杂多 Agent 出题层级。

## 任务定位

- 本任务同时受 [全局执行规则](../00-global-execution-rules.md) 约束；如与本任务具体要求冲突，以全局规则为准。

- 优先级 P1；风险高（pending 永久滞留、空题污染）。短生成同步完成，长生成使用持久作业、worker、幂等、租约、有限重试和明确终态。
- 非目标：不重写题库、不把每次生成强制异步、不新增第三层协调/规划/评分 Agent。

## 当前证据

- Finding 13 的候选为 `backend/app/api/v1/questions.py:174-218`、`services/question_generation_service.py:270-321`。问题：报告指出变式题可能只写入空 `pending` 占位，缺少队列消费者、worker、超时或重试；影响：任务可能永久 pending，空题会污染历史、批次和统计。
- 建议边界：报告建议以 Generation Job 统一短/长任务的状态与执行，短任务同步完成，长任务采用持久状态、worker、幂等、租约、有限重试和失败原因；预期收益：状态与执行一致并可复用给未来 AI 长任务。候选文件、行号、短/长任务和污染路径均须在当前代码中重验，建议不得视为已实施。

## 开始前调查

1. 阅读题目 API、生成服务、模型/迁移、AI provider、worker/队列、事务、管理查询和测试，搜索所有 `pending`、占位题和批次统计。
2. 定义请求幂等键、状态机（queued/running/succeeded/failed/expired/cancelled 等）、租约、超时、重试上限、死信/人工处理及题目发布时机。
3. 明确出题 Agent 产出→审题 Agent 复核→作业持久化的两层链路；若现状不同，先记录并按两层收敛，不增加层级。

## 允许修改范围

- 可修改生成 API、Job ORM/Schema/迁移、队列/worker Adapter、生成服务、管理状态查询和真实测试；迁移前核验 host/database/environment、备份并在隔离库完成 upgrade/downgrade 或恢复。
- 保持既有短任务同步响应及题库访问隔离；必要时增加兼容 DTO。

## 禁止操作

- 禁止向题库插入空题作为 pending、无限重试、无租约并发消费或仅靠内存状态。
- 禁止恢复多 Agent 层级、硬编码 provider 密钥、删除作业/题目历史，或将 provider 堆栈返回用户。

## 分阶段执行

1. 复核状态/消费者；2. 设计 Job 状态机、两 Agent 边界与事务；3. 先写状态/并发/崩溃测试；4. 最小实施 worker；5. 用真实队列/隔离环境跑成功、失败和恢复验收。

## 跨模块耦合检查

- 检查题目模型、题库/主库连接、ORM/迁移、API DTO、AI 预算与 run 诊断、worker 配置、Docker 和前端轮询/刷新；不得让 A 库 API 误连 B 库。
- 检查 P0-01 的答案隔离、P1-12 run ID、P1-10 预算预留与 Job 状态终止语义一致。

## 错误处理要求

- 用户仅见纯文本、可重试/不可重试的安全错误及作业安全摘要；失败原因分类不泄露 prompt、密钥、SQL 或堆栈。
- 每次领取、续租、重试、终态记录 job/run ID 和脱敏上下文；部分失败原子回滚或补偿，过期租约可安全接管。

## 验收标准

- 测试证明相同幂等键不重复创建/执行，多个 worker 仅一个持有有效租约，崩溃/超时后可恢复，重试恰到上限并进入明确终态；终态不可重新污染题库。
- 短任务同步可用；长任务按队列完成；成功题目必须经过且仅经过出题 Agent + 审题 Agent 两层，不能出现第三层 Agent 或空题占位。
- 数据库隔离迁移与回滚、真实 worker/API、预算/诊断关联、日志/健康/构建和 `git diff --check` 均通过。

## 最终报告格式

报告状态、文件和状态机、Finding 13 复核、两 Agent 证明、幂等/租约/重试/终态测试、数据库目标备份隔离迁移回滚、worker/API/日志/健康/Git 结果、提交 SHA、队列运维风险和人工步骤。
