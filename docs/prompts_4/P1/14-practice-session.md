# P1-14：练习会话（PracticeSession）

将本文件完整交给编码 AI 执行。前端验收必须使用内部浏览器真实流程、console、响应式检查和截图，不能只审代码或 mock。

## 任务定位

- 优先级 P1；风险中高（三类练习重复且隐式状态竞态）。建立单一 PracticeSession 状态机；课程、知识图谱、错题本页面仅作为来源 Adapter。
- 非目标：不改变已确认计分/答题事务，不把来源数据抓取混入状态机，不重写所有学习页面。

## 当前证据

- Finding 14 候选为 `frontend/src/components/quiz/quiz-practice.tsx:108-280`、`learning/[id]/page.tsx`、`knowledge-practice/page.tsx`、`wrong-book/practice/page.tsx`：十余相关 state 表达隐式状态，三类旅程重复。
- 建议集中题组、会话、提交、反馈、下一题、重试、结算和焦点；先逐页复核来源差异与后端契约。

## 开始前调查

1. 阅读三个页面、核心组件、store、API 类型、提交事务和现有测试；画出各来源的数据到 UI 状态转换和可访问性焦点规则。
2. 定义显式状态、事件、不可达状态、取消/卸载、重复提交和来源 Adapter 输入契约；未定义的产品差异先澄清。
3. 使用真实开发环境确认路由、登录前提、测试数据和浏览器可执行旅程。

## 允许修改范围

- 可修改练习组件/状态机、来源 Adapter、局部类型、相关 API 调用、无障碍行为和单元/集成/端到端测试。
- 若后端 DTO 或存储变动，核验 ORM/API/前端同步及目标数据库；迁移在隔离库验证升级与回滚。

## 禁止操作

- 禁止把状态机退化为更多布尔变量、让页面直接复制提交/反馈逻辑、用本地 mock 宣称真实验收，或绕开 P0-05 提交事务。
- 禁止吞掉失败并显示成功/空白，禁止删除学习/错题历史或硬编码真实数据。

## 分阶段执行

1. 复核三来源矩阵；2. 设计会话状态机与 Adapter 契约；3. 先写转换和竞态失败测试；4. 最小迁移三入口；5. 真实浏览器验收并迭代修复。

## 跨模块耦合检查

- 核验 QuestionBrief/Full 边界、答题提交 API、学习维度、错题/复习、前端类型、路由、加载状态和移动样式；来源不得泄露答案或误连题库。
- 与 P1-16 的 Journey 状态分工明确：PracticeSession 只负责一次练习，会话外目录/进度不混入。

## 错误处理要求

- 将 loading、empty、error、offline、retry、取消和结算失败映射为明确纯文本 UI；不显示 JSON、堆栈、SQL 或对象字符串。
- 记录脱敏 session/request ID、来源和状态转换；失败提交不可错误推进下一题，重复事件安全幂等。

## 验收标准

- 单元/集成测试覆盖课程、图谱、错题三来源的初始化、答题、反馈、下一题、重试、结算、空题组、网络失败、取消、重复点击和焦点转换，状态机无非法转换。
- 内部浏览器逐一完成三条真实练习流程；检查 Network 响应、console 无新增错误、键盘操作、loading/empty/error/offline/retry 和窄移动视口，并保存每条旅程截图路径。
- 回归确认提交事务、答案隔离和进度展示正确；构建、日志/健康、`git diff --check` 通过。

报告状态、文件和状态机/三 Adapter、Finding 14 复核、状态测试和真实 API 结果、内部浏览器操作/console/响应式/截图路径、构建/日志/健康/Git 结果、数据库证据（如适用）、提交 SHA、残余 UX 风险和人工步骤。
