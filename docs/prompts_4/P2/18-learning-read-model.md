- 非目标：不以未经测量的全局缓存掩盖问题，不改变学习规则、写入语义或跨数据库路由，不把 HTML 的候选行号当作当前事实。

## 当前证据

## 开始前调查

1. 阅读关联服务、路由、ORM/Schema、DTO、前端消费者、测试、数据库连接配置和 P0-05/P0-06/P0-07 的变更状态；记录 `git status` 与调用链。
2. 对每个目标请求建立可复现基线：固定数据规模与场景，记录查询总数、SQL 指纹、p50/p95 延迟、返回行数、重复调用行为和执行计划；区分主库、题库及 host/database/environment。
3. 先找出 N+1、重复聚合、随机排序和缺失/低效索引的真实根因，再选择批量加载、聚合投影、索引或局部缓存；没有基线不得实现优化。

## 允许修改范围

- 可修改相关读取服务、查询/投影、必要索引及其版本化迁移、缓存适配器和失效钩子、API DTO、前端读取适配、性能/集成测试与观测代码。
- 只在确认查询语义、权限过滤、数据源和失效事件后新增局部缓存；如有 Schema 变更，须采用 P0-07 的版本链并在独立可丢弃数据库验证。

## 禁止操作

- 禁止先加缓存后测量、使用无界或永久缓存、缓存跨用户/课程的未授权数据、以随机排序替代明确的查询策略，或把读优化扩展为无关重构。
- 禁止在唯一数据副本试验 migration/rollback，硬编码连接串、记录真实学生数据，或让 SQL、堆栈、内部对象/密钥出现在用户错误、日志或截图中。

## 分阶段执行

1. 调查并冻结代表性场景；2. 采集查询数与延迟基线；3. 设计最小读取边界、索引/投影和缓存键/TTL/失效矩阵；4. 先写会失败的查询预算、权限与失效测试；5. 最小实施；6. 在相同场景复测、回归与审计。
- 任何缓存仅在写入成功后按设计失效或更新；失效失败必须可观测、不能向用户伪造新鲜数据。

## 跨模块耦合检查

- 检查课程、进度、成就、每日挑战与答题写入的 ORM、Schema/迁移、索引、事务、API DTO、前端类型和展示是否一致；核对主库/题库路由、Docker 与环境变量不串库。
- 与 P0-05 的提交事务、P0-06 的学习维度和 P0-07 的迁移顺序协调；读取模型不得绕过授权、账户状态或已建立的数据访问边界。

## 错误处理要求

- 查询超时、缓存不可用、投影缺失或失效失败应记录脱敏请求/主体/课程标识、查询指标和相关 ID；按设计降级为正确但可能较慢的受权读取，或返回清晰纯文本可重试提示。
- 不向用户暴露 SQL、执行计划、堆栈、连接串、令牌或对象字符串；事务/迁移失败应回滚并保留可诊断日志。

## 验收标准

- 在同一固定场景与数据规模下给出优化前后查询数、SQL 指纹和 p50/p95 延迟证据；优化后的查询预算可由测试执行，响应数据、排序、权限和空态与基线契约一致。
- 覆盖多个课程/用户、无数据、权限拒绝、写后读取、并发写入及缓存命中/未命中；证明课程、进度、成就或答题写入后相关缓存按矩阵失效，绝不返回过期授权范围或陈旧进度。
- 迁移/索引在隔离数据库验证 upgrade/downgrade 或恢复路径；测试、日志、健康检查、构建及 `git diff --check` 通过。
