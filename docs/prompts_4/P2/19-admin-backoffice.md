# P2-19：管理后台（Admin Backoffice）

将本文件完整交给编码 AI 执行。遵守既有认证、CSRF、审计和“出题 Agent + 审题 Agent”两层全局约束；本任务的目标是深化业务边界，绝非按文件长度机械拆分。

## 任务定位

- 优先级 P2；风险中高。将后台的课程编排、用户治理和题库运营等真实业务规则收敛为可测试模块，令路由仅承担请求解析、授权装配与响应呈现。
- 非目标：不改变既定权限策略、批量删除语义或页面功能，不以移动函数/模板作为完成标准，不依据旧报告行号直接修改。

## 当前证据

- Finding 19 候选为 `backend/app/admin/routes.py`（1600+ 行）和 `backend/app/admin/templates/*`：认证、HTML、课程/用户/课时/题目读写混杂，并存在宽泛异常捕获。
- 报告建议按课程编排、用户治理和题库运营深化模块；执行前必须重新核实当前函数、授权点、事务范围、模板调用和跨路由不变量。

## 开始前调查

1. 阅读后台路由、模板、依赖注入、模型、服务、审计、认证/CSRF、测试及相关 P0-02/P0-03/P1-09 实施结果；搜索每个管理入口和宽泛 `except`。
2. 绘制真实业务流程：操作者、授权条件、输入校验、领域规则、事务边界、审计事件、模板/重定向和错误映射；用调用关系而非文件大小决定模块边界。
3. 在修改前通过内部浏览器逐项走查当前管理登录和关键课程、用户、题库流程，记录可复现起点与无敏感信息的截图基线。
4. 如设计可能改变数据库 Schema 或数据，先记录并核验目标 `host`、`database`、`environment` 符合预期，建立可恢复备份；只在独立、可丢弃测试数据库演练 migration，绝不在唯一数据副本上试验。

## 允许修改范围

- 可修改后台路由/模板、领域服务、DTO/表单校验、事务和审计适配、针对性测试，以及支持上述边界的最小依赖注入代码。
- 允许新增课程编排、用户治理、题库运营等服务，但每个服务必须有明确输入/输出、授权前提和事务责任；路由应保持薄而不丢失安全检查。
- 如确需 Schema/数据迁移，只允许使用版本化迁移及经验证的 upgrade/downgrade 或隔离 restore/rollback 路径。

## 禁止操作

- 禁止仅为减少行数而拆文件、复制授权/事务规则、吞掉异常、把业务规则塞进模板，或在没有授权/引用审计与用户明确授权时删除管理数据或路由。
- 禁止放松 CSRF、会话、角色/账户状态检查，使用 mock 代替真实后台浏览器验收，或暴露 SQL、堆栈、令牌与个人数据。
- 禁止未核验目标或未完成可恢复备份即执行 migration、rollback、数据回填或删除；禁止在唯一数据副本演练任何数据库变更。

## 分阶段执行

1. 调查和边界映射；2. 如涉及数据库，核验目标并建立备份，在独立可丢弃库设计并演练迁移/恢复；3. 为一个业务域设计路由—服务—审计契约及迁移策略；4. 先补契约/授权/事务失败测试；5. 逐域最小迁移并保持路由兼容；6. 真实浏览器回归所有关键流程；7. 再处理下一域。
- 每次只迁移一个可验证领域；发现权限、CSRF 或审计不变量不清楚时停止设计并先澄清，而非猜测实现。

## 跨模块耦合检查

- 检查认证会话、CSRF、账户主体、角色权限、课程/课时/题目/用户 ORM 与 DTO、模板字段、重定向路由、事务和审计事件的一致性。
- 与 P0-02、P0-03、P1-09 的安全边界串行协调，不并行编辑共享认证/管理配置；如改动题目 AI 入口，保留出题 Agent 与审题 Agent 两层约束。
- 涉及持久化时，同步核对 ORM、Schema、版本化迁移、外键/索引、迁移前后 API DTO/模板字段、备份/恢复和主库/题库路由；不得使 A 库 API 误连 B 库。

## 错误处理要求

- 将领域校验、未授权、冲突、缺失和基础设施错误映射为清晰纯文本页面提示或安全重定向；不得把异常对象字符串、JSON、SQL 或堆栈呈现给管理员。
- 使用结构化脱敏日志和审计记录操作者、领域动作、目标 ID、结果、相关请求 ID；写入失败必须回滚，审计失败策略须显式并可测试。

## 验收标准

- 每个迁移域都有路由/服务契约回归：授权/未授权、CSRF、有效/无效输入、冲突、事务回滚、审计和模板响应均受测；业务不变量只在一个明确服务边界维护。
- 内部浏览器以真实管理员身份完成登录、课程编排、用户治理和题库运营的代表性读写流程；验证重定向/错误提示、会话和 CSRF，检查 console，无新增错误，并保存脱敏截图。
- 证明不是机械拆分：路由仅做装配，服务承载规则/事务/错误映射，重复逻辑减少且不改变既有公共契约；测试、构建、日志、健康及 `git diff --check` 通过。
- 如有数据库变更，提供每次操作前已核验的 `host`/`database`/`environment` 和可恢复备份证据；在独立可丢弃数据库实际完成 migration upgrade/downgrade，或完成 restore/rollback，并证明数据完整性与路由/服务契约回归。

## 最终报告格式

报告 Finding 19 重验、实际领域边界和未迁移原因、文件与契约变化、授权/CSRF/事务/审计回归结果、数据库目标 `host`/`database`/`environment` 核验和备份结果、隔离库 migration upgrade/downgrade 或 restore/rollback 及完整性证据、真实后台浏览器流程/console/截图路径、测试/构建/日志/健康/Git 结果、提交 SHA、残余边界风险与人工回归步骤。
