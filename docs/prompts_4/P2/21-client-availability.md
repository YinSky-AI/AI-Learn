# P2-21：客户端可用性（Client Availability）

将本文件完整交给编码 AI 执行。必须以内部浏览器完成真实流程、检查 console 和保存截图；如触及 AI 入口，保持“出题 Agent + 审题 Agent”两层全局约束。

## 任务定位

- 本任务同时受 [全局执行规则](../00-global-execution-rules.md) 约束；如与本任务具体要求冲突，以全局规则为准。

- 优先级 P2；风险中。统一客户端对网络、请求和 PWA 生命周期的可见状态与可访问交互，使用户明确知道数据是实时、缓存、失败还是更新中。
- 非目标：不把失败伪装为空数据或成功，不重写所有页面，不仅凭组件测试宣称完成，也不把报告候选行号当作现状。

## 当前证据

- Finding 21 的候选为 `frontend/src/stores/loading-store.ts`、`components/common/error-state.tsx`、`public/sw.js`、`components/pwa/*`、`wrong-book/page.tsx`。问题：报告指出页面可能各自组合 loading/error/offline/PWA 更新，部分失败可能伪装为空数据，部分 Badge 可能缺少按钮语义；影响：用户可能无法分辨实时、缓存或失败状态，离线更新和键盘体验可能不一致。
- 建议边界：报告建议统一 pending、ready、empty、failed、offline-cached、updating、installable 状态及可访问性播报，由 Availability State 经 HTTP/SW Adapter 供页面使用；预期收益：一处实现为全部页面提供移动端、PWA 和无障碍 leverage。候选文件、行号、每页状态来源、HTTP/SW 事件、缓存策略、PWA 清单、交互元素、辅助技术语义和结论均须在当前代码中重验，建议不得视为已实施。

## 开始前调查

1. 阅读相关 store、组件、页面、请求客户端、Service Worker、PWA 配置、测试、类型、后端错误契约及 P1-14/P1-15/P1-16 的状态边界；记录 `git status` 和调用链。
2. 定义并获团队确认的显式状态表：`pending`、`ready`、`empty`、`failed`、`offline-cached`、`updating`、`installable`；对每个状态规定触发条件、显示文案、可用操作、焦点、ARIA 播报和恢复转移。
3. 以内部浏览器采集在线、网络断开、缓存可用/不可用、更新可用、安装可用、空数据、服务错误和重试的当前行为；检查桌面与移动视口及 console。

## 允许修改范围

- 可修改状态模型/store、共享状态组件、请求/SW/PWA 适配、必要页面接入、可访问性语义、前端类型、测试和浏览器验收脚本。
- 可为状态机新增小型纯函数和单一共享 UI 边界；页面只能通过已定义状态消费，不得保留将失败折叠为空态的旧 fallback。

## 禁止操作

- 禁止用多个松散布尔值重新表达隐式状态机、让离线缓存伪装实时数据、自动应用更新而不告知用户，或使用不可键盘操作的 `div`/Badge 冒充按钮。
- 禁止绕过服务端权限/错误契约、缓存敏感数据超出既有策略、把 console 错误忽略掉，或向用户显示 JSON、堆栈、SQL、令牌和内部对象。

## 分阶段执行

1. 调查状态来源和真实浏览器基线；2. 设计状态表、状态转移、HTTP/SW 适配和可访问性契约；3. 先写状态转换、渲染和键盘测试；4. 最小接入一个共享边界与代表页面；5. 逐步替换重复组合；6. 完成浏览器、PWA、移动端和回归验收。
- 任何无法映射到明确状态的错误都必须保留为 `failed`，提供安全的重试/返回操作，不能静默降级为 `empty`。

## 跨模块耦合检查

- 检查前端请求错误格式、API DTO、认证/刷新、学习 Journey/练习/辅导状态、缓存键、Service Worker、manifest、PWA 安装/更新、路由、移动布局与后端网关错误响应的一致性。
- 若接口变更，验证服务端纯文本脱敏错误、前端解析和页面显示同步；不得破坏 P1-14/P1-15/P1-16 已定义的会话、对话和学习契约。

## 错误处理要求

- 用户提示使用清晰纯文本，准确说明失败、离线缓存或更新状态及下一步；错误区域可被读屏公告，重试结果和焦点移动可预测。
- console/日志只记录脱敏上下文、状态和请求关联 ID；不得记录令牌、个人数据、响应机密或对象字符串。网络/更新失败要可恢复且不丢失用户输入。

## 验收标准

- 自动测试覆盖全部七种状态、关键转移、失败不等于空态、重试、离线缓存标识与更新/安装触发；所有可操作控件具备正确原生/ARIA 语义、可聚焦名称和键盘操作。
- 内部浏览器执行在线、离线且有缓存、离线无缓存、服务失败、恢复网络、更新提示与应用、安装提示/取消的真实流程；使用键盘完整操作，并以可用读屏工具或可验证的 ARIA live/焦点证据确认播报。
- 在桌面与移动视口检查布局、触控目标和横向溢出；检查 console 无新增错误，保存每个关键状态的脱敏截图。测试、构建、日志/健康（如适用）与 `git diff --check` 通过。

## 最终报告格式

报告 Finding 21 重验、状态表与转移、实际文件和 HTTP/SW/PWA 契约、状态/键盘/读屏测试、在线/离线/更新/安装浏览器流程、桌面/移动/console 与截图路径、构建/Git 结果、提交 SHA、剩余浏览器或平台限制和人工验收步骤。
