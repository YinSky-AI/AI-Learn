# prompts_3 学习平台重构设计

## 目标与范围

将已有课程、题库、学习会话和 SSE 对话能力重构为可验证的学习闭环，并完整交付 `agents/prompts_3` 的 12 项功能。本次范围以 `prompts_3` 为准；`prompts_2` 的 8 层出题闭环、PID、自进化和相关复杂编排明确不纳入实现。

工作区现有未提交的课程与题库改动属于在制内容。本项目改动不得覆盖、回退或混入这些改动。

## 架构边界

### 两层 AI 出题

AI 出题只包含两个 Agent：

1. 出题 Agent：接收学科、知识点、难度、题型、数量和变式来源；生成结构化题目、答案与解析。
2. 审题 Agent：检查答案正确性、难度与适龄性、结构完整性和重复风险；不通过时给出可执行的修订原因。

`QuestionPipeline` 是这两个 Agent 的唯一编排入口。它最多进行有限次“生成 → 审题 → 修订”循环，之后保存通过的题目、批次、审题结果和工具日志。生成失败或审题未通过必须以用户可理解的纯文本错误返回，并写入服务端日志。

旧的 8 层出题 Harness 不再承担出题职责。`harness.py` 将只承载独立的辅导编排器，避免两种职责混杂。

### 四 Agent 辅导

辅导系统与出题系统独立。讲解老师、提问助教、学习诊断师、鼓励师通过 `SharedState` 共享当前题目、学生回答、会话上下文、诊断和建议。辅导默认采用引导式表达，不直接代做题目；当用户连续受挫时，鼓励师以适龄、非评判的语言介入。

### 产品闭环

答题提交返回正确性、标准答案、解析、知识点、建议和可选辅导入口。答错题目自动加入错题本；行为模型从答题记录增量更新，并提供学习报告和知识图谱的数据基础。积分、等级、连胜和成就在答题事务内更新，并以可消费的通知事件返回前端。

## 分阶段实施

1. 基线重构：清理重复路由，统一错误响应与请求追踪，规范数据库迁移和会话边界，补齐后端测试依赖及浏览器测试基础。
2. 核心 AI 与反馈（prompts_3 01–05）：两层出题、持久化、四 Agent 辅导、辅导 UI、答题反馈。
3. 学习留存（06–09）：错题本、游戏化、行为模型与报告、知识图谱。
4. 交付扩展（10–12）：PWA 与移动端、每日挑战和排行榜、全局 AI 浮动入口。

各阶段只在其 API 契约、前端类型、模型和迁移同步后继续下一阶段。数据结构变动通过可追踪迁移执行，禁止仅依赖启动时建表。

## 错误处理与可观测性

- API 错误使用统一响应格式，只对用户暴露简短中文文本；字典型异常优先提取 `message`。
- 每个 AI 请求具有请求 ID 和运行 ID；记录耗时、失败阶段和脱敏后的输入输出摘要。
- AI Provider 不可用时不伪造成功结果，返回明确的可重试提示。
- 关键持久化操作使用事务：失败时回滚，不留下半完成批次、错题或积分数据。

## 验收策略

- 后端：单元/API 测试覆盖两层出题、审题拒绝重试、工具持久化、答题反馈、错题本、积分与权限边界。
- 前端：类型检查和生产构建；关键用户旅程的真实浏览器测试。
- 容器：每次应用代码改动后执行 `docker compose up -d --build`，检查 `docker compose ps` 与服务日志。
- 视觉：桌面和移动视口截图，检查中文文案、导航、学习页、辅导面板、错题本、报告和全局入口；发现问题最多自主迭代三轮。
- 证据：将测试输出、容器日志摘要、截图与视觉自检结论保存到项目内验收目录。

## 非目标

- 不实现 prompts_2 的 8 层出题、PID 控制或提示词自进化。
- 不接入联网搜索、外部教材库、视频、直播、家长端或社区功能。
- 不在本轮引入真实推送通知；PWA 只实现离线基础能力与可安装性。
