# 项目 Agent 指令重构设计

## 1. 背景

仓库根目录原有 `agent.md` 不是 Codex 默认自动发现的标准文件，并且仍将项目描述为八层出题、PID 反馈与 SummaryAgent 自进化系统，还引用不存在的 `agents/` 目录和失效的绝对路径。这与当前代码、`docs/prompts_3/` 的两层出题实现及 `docs/prompts_4/` 的执行约束冲突。

本次只重构项目指令与文档入口，不修改业务代码、配置、数据库、Docker 或 prompts_4 任务正文。

## 2. 方案比较

### 方案 A：只改现有 `agent.md`

文件改动最少，但文件名不是标准 `AGENTS.md`，新会话可能不会自动加载，prompts_4 中对 `AGENTS.md` 的引用仍然失效。

### 方案 B：新增 `AGENTS.md`，保留旧 `agent.md`

兼容旧链接，但两个入口容易重复、漂移或被误读，无法满足根目录只保留一个指令文件的要求。

### 方案 C：根目录只保留标准 `AGENTS.md`（采用）

先从旧 `agent.md` 提取仍然有效的项目约束，再删除旧文件。根目录只保留 Codex 可自动发现的 `AGENTS.md`；同步更新活动文档入口。归档文档可以保留旧文件名作为历史事实，但不得将其作为当前入口。

## 3. 文件职责

### `AGENTS.md`

它是仓库唯一权威的 Agent 工作规则，包含：

1. 文件用途与当前项目事实。
2. 文档权威顺序。
3. FastAPI、Next.js、PostgreSQL、Redis、两层 AI 出题和四角色辅导摘要。
4. 调查、计划、实施、自主验收和报告流程。
5. 文件、删除、密钥、数据库、错误处理与跨模块耦合规则。
6. 按变更类型区分的验证矩阵和内部浏览器截图要求。
7. prompts_4 一次只实施一个任务、逐项验收后继续的协议。
8. Git 分支、Conventional Commits、受保护 main、PR 与 Squash merge规则。

该文件不参与 Python、前端、Docker 或数据库运行，不写本机绝对项目路径。

### `docs/INDEX.md`

只链接根目录 `AGENTS.md` 作为 AI 工作规则入口，并保持 prompts_3“当前设计依据”和 prompts_4“尚未实施待办”的状态区别。

### 历史文档

`docs/prompts_1/` 与 `docs/archive/` 可能描述早期 `agent.md`。活动入口必须改为 `AGENTS.md`；归档材料中的旧名称只代表当时事实，不恢复旧架构。

## 4. 权威顺序

发生冲突时按以下顺序判断：

1. 当前代码、数据库模型、迁移和可执行测试是实现事实。
2. 根目录 `AGENTS.md` 是执行与安全规则。
3. `docs/prompts_3/` 是当前已实施功能的设计依据，但仍需以代码复核。
4. `docs/prompts_4/` 是尚未实施的优化待办，不代表当前状态。
5. `docs/prompts_1/` 是早期产品背景。
6. `docs/prompts_2（已废弃）/` 是历史题库方案，不得恢复其复杂多层出题架构。

若设计文档与实际代码不一致，Agent 必须先报告差异并以调查结果制定最小修改方案，不能根据旧行号直接改动。

## 5. 当前架构声明

- AI 出题只能由“出题 Agent + 审题 Agent”两层组成；允许有限的生成、审题和修订循环，不增加第三层出题 Agent。
- TutorHarness 的四个辅导角色不得参与出题流水线。
- 外部 LLM Provider 调用属于允许的模型能力；默认不进行网页搜索、爬取或外部教材检索，除非任务明确授权。
- prompts_2 中的八层出题、PID、FeedbackAggregator 和 SummaryAgent 自进化不再是当前强制架构。

## 6. 执行与风险规则

- 多文件任务先列出计划和影响范围。
- 删除文件、数据、数据库、容器或高风险配置前先核验引用和目标，并取得明确授权。
- 数据库操作前核验 host、database、environment；迁移与恢复先在隔离可丢弃数据库验证，并准备备份和回滚。
- 数据层、ORM、API DTO、前端类型、展示、网关与环境变量必须做耦合检查。
- 面向用户的错误为清晰纯文本，不暴露异常堆栈、SQL、密钥或内部对象；对象错误提取 `message`。
- 代码变更执行对应测试、构建、容器状态、日志和回归检查；仅修改文档时不无意义地重建 Docker。
- UI 变化必须使用内部浏览器完成真实操作、控制台、响应式与截图验收。

## 7. Prompts 4 协议

- 开始前读取 `docs/prompts_4/README.md`、全局执行规则和依赖驱动实施顺序。
- 一次只实施一个任务文件；只有本项验收通过后才进入下一项。
- HTML 报告中的候选文件与行号必须在当前代码中重新核验。
- 每项任务独立提交，并在 README 清单中区分“提示词存在”和“功能已实施”。
- 用户一次授权完整优化包时可以按顺序连续推进，但不能并行修改共享模型、认证、数据库连接或全局配置；高风险操作仍需单独确认。

## 8. 验收

完成后必须满足：

- 根目录存在且只存在一个 Agent 指令入口 `AGENTS.md`，不存在 `agent.md`。
- `AGENTS.md` 不包含本机绝对项目路径。
- 当前文档入口不再引用旧 `agent.md`；归档中的旧名称明确属于历史记录。
- 两层出题、四角色辅导、错误脱敏、数据库目标核验、内部浏览器、prompts_4 协议和 Git 规则均明确存在。
- 本次修改文件的相对 Markdown 链接可解析。
- Git 变更只涉及 `AGENTS.md`、`agent.md`、`docs/INDEX.md`、早期提示词权威说明和本设计/实施计划文档。
- `git diff --check` 通过。
