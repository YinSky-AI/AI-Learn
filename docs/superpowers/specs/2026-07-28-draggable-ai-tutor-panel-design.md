# AI 辅导悬浮窗拖动设计

## 目标与范围

让展开后的 AI 辅导对话窗口可在桌面端视口内自由拖动。右下角入口按钮保持固定；移动端继续使用现有近全屏布局。本次不增加窗口缩放、跨页面或刷新后的坐标持久化，也不引入第三方拖拽依赖。

## 当前实现

`frontend/src/components/ai/floating-ai-button.tsx` 使用 `closed`、`open`、`minimized` 三种状态控制入口按钮和对话面板。对话面板通过固定的 `bottom`、`right` 样式定位，没有坐标状态或指针事件。顶部标题栏包含最小化与关闭按钮，适合作为唯一拖动手柄。

## 设计

新增局部 `useDraggablePanel` Hook，负责指针捕获、坐标计算、视口边界约束和窗口尺寸变化后的重新校正。组件为面板绑定元素引用和位置样式，为标题栏绑定 Pointer Events。

交互规则：

- 仅在桌面断点启用拖动；移动端不注册有效拖动行为。
- 仅标题栏空白区域和标题区域可发起拖动；最小化与关闭按钮仍只执行原操作。
- 按下时记录指针起点和面板当前位置，移动时计算新坐标，松开或指针取消时结束拖动并释放捕获。
- 坐标必须限制在视口安全边距内，确保完整标题栏和操作按钮始终可见。
- 拖动中使用 `grabbing` 光标并禁止文本选择；结束后恢复。
- 最小化或关闭后再次打开时保留当前页面会话内的位置；刷新页面后恢复默认右下角位置。
- 浏览器窗口缩放时重新约束已有坐标，避免面板留在视口之外。

数据流：

```text
标题栏 pointerdown
→ 读取面板矩形与指针起点
→ pointermove 计算候选坐标
→ 按视口和安全边距约束
→ 更新 fixed 面板的 left/top
→ pointerup/pointercancel 释放捕获并结束拖动
```

## 文件范围

- `frontend/src/components/ai/floating-ai-button.tsx`：接入拖动 Hook、面板引用、位置样式和标题栏交互状态。
- `frontend/src/hooks/use-draggable-panel.ts`：封装拖动状态、Pointer Events 和边界校正。
- `frontend/tests/floating-ai-button.test.mjs`：覆盖拖动手柄接入、移动端约束和原有打开/关闭/最小化能力。
- 若现有前端测试结构适合纯函数测试，可为边界计算增加一个聚焦测试文件；不扩大到无关组件。

## 异常与兼容处理

- 收到 `pointercancel`、组件卸载或窗口失焦时必须结束拖动，避免残留拖动状态。
- 不读取聊天内容，不改变 Tutor API、课程上下文或对话状态。
- 位置更新只影响客户端样式，不产生服务端渲染差异和持久化数据。
- 保留标题栏按钮的键盘焦点、可访问名称和点击行为。

## 验收标准

1. 桌面端可通过标题栏流畅拖动展开面板，输入框、消息区及标题栏按钮仍可正常操作。
2. 面板不能被拖出视口安全边界，窗口缩放后仍可找回并操作。
3. 最小化、恢复、关闭和重新打开行为正确，入口按钮始终固定在原位置。
4. 移动端布局、底部导航避让和触摸滚动保持现状。
5. 相关前端测试、类型检查和生产构建通过；Docker 重建后服务健康。
6. 使用 Codex 内部浏览器完成桌面拖动、边界、恢复、移动端和控制台检查，并保存验收截图。
